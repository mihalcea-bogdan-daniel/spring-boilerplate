# Translations (i18n)

Every text a user can see or hear (labels, headings, placeholders, tooltips, `aria-label`, `alt`, toasts,
confirm dialogs, empty states) comes from a locale file. Nothing user-facing is written inline in a page.

Built on [`@nuxtjs/i18n`](https://i18n.nuxtjs.org) (vue-i18n underneath).

| What | Where |
| --- | --- |
| Messages | [`i18n/locales/en.json`](../i18n/locales/en.json) (source of truth), [`ro.json`](../i18n/locales/ro.json) |
| Languages, detection | `i18n` block in [`nuxt.config.ts`](../nuxt.config.ts) |
| Date formats | [`i18n/i18n.config.ts`](../i18n/i18n.config.ts) (`date`, `datetime`) |
| PrimeVue's own texts | [`i18n/primevue.ts`](../i18n/primevue.ts) (paginator, filters, password strength, calendar) |
| `<html lang>` + PrimeVue sync | `useLocaleSync()` in `app.vue` |
| Language picker | `<LocaleSwitcher />` in both layouts |

## How the language is chosen

1. The `i18n_locale` cookie, if set (the picker sets it).
2. Otherwise the browser's `Accept-Language`, on the first visit.
3. Otherwise English.

URLs carry no locale prefix (`strategy: 'no_prefix'`): the host name already selects the tenant, and
`/admin/users` stays `/admin/users` in every language. The server renders in the cookie's language, so there
is no flash of English.

Every API call sends `Accept-Language` with the current locale (`plugins/api.ts`), so Spring can localise
Bean Validation messages. `detail` texts the backend writes itself are English today; show them as they come.

## Using it

```vue
<script setup lang="ts">
const { t, d } = useI18n()

const res = await request('/admin/projects', {
  method: 'POST', body: form,
  success: t('projects.created'),
  error: t('projects.createFailed'),
})

confirm.require({
  header: t('projects.deleteHeader'),
  message: t('projects.deleteConfirm', { name: p.name }),
  acceptProps: { label: t('common.delete'), severity: 'danger' },
  rejectProps: { label: t('common.cancel'), severity: 'secondary', outlined: true },
  accept: () => { /* … */ },
})
</script>

<template>
  <h1 class="page-title">{{ t('projects.title') }}</h1>
  <Button :label="t('projects.new')" icon="pi pi-plus" />
  <Column field="name" :header="t('common.name')" />
  <Button icon="pi pi-trash" text rounded :aria-label="t('common.delete')" />
  <LoadError :error="error" :what="t('projects.what')" @retry="refresh()" />
  <span>{{ d(p.createdAt, 'datetime') }}</span>
  <Tag :value="t(`status.${u.status}`)" />
</template>
```

- **Attributes need the colon.** `label="Save"` is raw text; `:label="t('common.save')"`.
- **Markup inside a sentence** (a `<code>`, a `<strong>`): use `<i18n-t>` with named slots, never `v-html`:

  ```vue
  <i18n-t keypath="apiKeys.intro" tag="p" class="muted">
    <template #header><code>X-API-Key</code></template>
  </i18n-t>
  ```
  with `"intro": "Send the key in the {header} header."`
- **Dates** go through `d(value, 'date' | 'datetime')`, never `toLocaleString()`. ISO strings from the API
  work directly.
- **Enums from the API** (`ACTIVE`, `PENDING`…) are shown with ``t(`status.${value}`)``. For a `Select`, map them
  to `{ label, value }` in a `computed` so the labels follow a language switch.
- **Menus and option lists** built in `<script>` must be `computed`, or they stay in the old language.
- In `.ts` files (composables, stores) call `useI18n()` inside the composable function. `utils/` stays
  framework-free: take a `t` parameter, like `utils/feedback.ts`.
- A slot variable named `t` (`#body="{ data: t }"`) hides the `t()` function: name rows `row`.

## Keys

- Grouped by screen: `users.*`, `roles.*`, `tenants.*`, `profile.*`, `auth.*`. Shared words live in `common.*`
  (`save`, `cancel`, `delete`, `name`, `email`…). Reuse them before adding a new one.
- `camelCase`, describing the meaning, not the English text: `users.deleteConfirm`, not `users.deleteThisUser`.
- Placeholders are named: `"Delete {email}?"` and `t('users.deleteConfirm', { email })`. Never concatenate
  translated fragments; word order differs between languages.
- `feedback.*` belongs to `utils/feedback.ts` (the default toast titles). `status.*` holds API enum labels.
- `loadError.*`: `what` is a translated noun phrase with its article where the language needs one
  (`"users"` / `"utilizatorii"`).

## Adding a key

1. Add it to `en.json`.
2. Add the same key to every other locale file, translated. Do not copy the English text into `ro.json`.
3. `npm run lint && npm test`.

## Adding a language

1. A line in `i18n.locales` in `nuxt.config.ts`: `{ code: 'de', language: 'de-DE', name: 'Deutsch', file: 'de.json' }`.
2. `i18n/locales/de.json` with every key from `en.json`.
3. `datetimeFormats.de` in `i18n/i18n.config.ts`.
4. PrimeVue texts under `de` in `i18n/primevue.ts`.
5. Add the import to `tests/i18n.test.ts`.

## What is enforced

| Check | Catches |
| --- | --- |
| `@intlify/vue-i18n/no-raw-text` (lint) | literal text in templates and in `label`, `header`, `placeholder`, `title`, `alt`, `aria-label`, `value`, `summary` |
| `@intlify/vue-i18n/no-missing-keys` (lint) | `t('typo.key')` |
| `@intlify/vue-i18n/no-missing-keys-in-other-locales` (lint) | a key added to `en.json` only |
| `@intlify/vue-i18n/no-v-html` (lint) | HTML injected through messages |
| `tests/i18n.test.ts` | locales with different keys or different `{placeholders}` |
| `tests/feedback.test.ts` | toast keys missing from `en.json` |

Lint does not see strings in `<script>` (toasts, confirm dialogs, menu items). Those are on you; the review
question is "would a Romanian user see English here?".

Allowed literals (`ignoreText` in `eslint.config.mjs`) are format examples in placeholders (`acme`,
`xxxxx-xxxxx`), header names (`X-API-Key`) and `IP`. Add to that list only for text that is the same in every
language.
