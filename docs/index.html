A multi-tenant SaaS starter, ready to run.

Spring Boot API with one PostgreSQL schema per tenant, a Nuxt dashboard, and sign-in, roles, audit and billing-ready plans already wired. Clone it, run four commands, and start on your own domain model.

Spring Boot 3.5 · Java 17+PostgreSQL 16 Nuxt 4 · TypeScriptPrimeVue 4 GradleInstallable PWAEnglish · Română

Overview

Schema per tenantThe sub-domain picks the tenant; each one gets its own t_<slug> schema, migrated by Flyway at startup.
Every sign-in methodPassword, e-mail code, Google and GitHub, passkeys, authenticator-app MFA, API keys.
Admin dashboardUsers, roles and permissions, settings and branding, API keys, audit log.
Platform consoleSuper-admins provision, suspend, inspect and delete tenants, and can sign in as a tenant user.
Safe by defaultRefuses to start in production with dev secrets; rate limits, breached-password check, encrypted secrets.

Run locally

Three terminals: database and mail, backend, frontend.

  1. Clone and start PostgreSQL + Mailpit 
    git clone https://github.com/mihalcea-bogdan-daniel/spring-boilerplate.git
cd spring-boilerplate
docker compose up -d postgres mailpit
  2. Start the backend (dev profile, port 8080) 
    cd backend
./gradlew bootRun --args='--app.seed=true'   # omit --args to start without demo data
    The first start creates the platform tenant and a super-admin; --app.seed=true adds the demo tenants acme and globex.
  3. Start the frontend (port 3000) 
    cd frontend
npm install
npm run dev
  4. Sign in
    OpenAsCredentials (dev only)
    admin.localhost:3000Super-adminsuperadmin@admin.localhost / ChangeMe!123
    acme.localhost:3000Tenant admin (demo data)admin@acme.test / Demo-Passw0rd!
    localhost:8025Mailpitsign-in codes and invitations land here
    localhost:8080/api/docs/uiSwagger UIsend X-Tenant-ID: platform
In dev, Nuxt proxies /api to the backend and keeps the Host header, exactly like nginx in production, so acme.localhost:3000 lands in the acme tenant.

Full stack in Docker

Postgres, Mailpit, backend, frontend and nginx, the same shape as production.

cp .env.example .env      # then set JWT_SECRET and SUPER_ADMIN_PASSWORD
docker compose up --build

Open admin.localhost for the platform console and http://<slug>.localhost for a tenant. The backend runs with the prod profile here, so it refuses to start with placeholder secrets. Generate them with:

openssl rand -base64 48   # JWT_SECRET
openssl rand -base64 32   # APP_ENCRYPTION_KEY

How tenants work

The host name decides the tenant. Pages never pass a tenant id; the backend works it out before any controller runs.

https://acme.example.com/api/admin/users
  nginx            keeps Host, adds X-Forwarded-* (trusted only from proxy addresses)
  tenant filter    custom domain? → <slug>.<base-domain>? → tenant "acme"
  JWT check        the token's tenant must be "acme"
                   … unless it is a platform SUPER_ADMIN sending X-Tenant-ID: globex
  @PreAuthorize    hasAuthority('user:read')
  Hibernate        search_path → t_acme, reset to public when the connection returns
HostTenant
acme.example.comacme, schema t_acme
portal.customer.comthe tenant whose custom domain matches
admin.example.complatform, home of super-admins
anything else404 Unknown tenant

New tenant: Platform → Tenants → New creates the schema, runs the tenant migrations, creates the first admin and e-mails an invitation. A new migration file rolls out to every tenant on the next start.

Sign-in methods

MethodNotes
E-mail + passwordBCrypt, lockout after 5 failures, breached passwords rejected
E-mail code6 digits, 10 minutes, 5 attempts
Google, GitHubset the client id and secret; only verified e-mails are accepted
Passkeysadded from the profile; bound to the workspace host; counts as two-factor
Authenticator appTOTP with recovery codes, required after any password, code or social sign-in once enabled
API keysX-API-Key header, for plans with the api-keys feature

Sessions use a 15-minute access token and a rotating refresh token in an HttpOnly cookie. Changing the password, disabling a user or changing their roles takes effect immediately.

Adding a feature

  1. Migration in backend/src/main/resources/db/migration/tenant/: the table, plus the new permissions (project:read, project:write).
  2. Entity, repository, service, controller under com.polygis.<module>; guard endpoints with @PreAuthorize("hasAuthority('project:read')").
  3. Integration test extending IntegrationTestBase (embedded PostgreSQL; no Docker needed).
  4. Texts in frontend/i18n/locales/en.json and the same keys, translated, in every other locale file. Pages never contain literal text; lint fails if they do (i18n guide).
  5. Page in frontend/app/pages/admin/, following the page recipe: useApi() + <LoadError> to show data, useRequest() for buttons, t('…') for every text, definePageMeta({ permission }).
  6. Menu entry in frontend/app/layouts/default.vue.
Coding agents: read frontend/AGENTS.md first. It lists the components to use, how errors become toasts, the i18n rule, and the files not to touch.

Production checklist

  • Secrets come from a secret store, not .env in the image.
  • Wildcard TLS certificate for *.example.com (DNS-01); custom domains need their own.
  • The backend is reachable only from nginx and the Nuxt server; TRUSTED_PROXIES matches your proxy.
  • limit_req on /api/auth/ at nginx, on top of the built-in limits.
  • Backups include public and every t_* schema.
  • Social-login redirect URIs registered per tenant host, or one central callback host (OAUTH2_REDIRECT_BASE).
  • Sentry DSNs set, and source maps uploaded with SENTRY_AUTH_TOKEN in CI.

Troubleshooting

acme.localhost does not open

Safari and some tools don't resolve *.localhost. Use Chrome, Edge or Firefox, or add a line per tenant to /etc/hosts, e.g. 127.0.0.1 acme.localhost admin.localhost.

Backend refuses to start: "Unsafe configuration for profiles …"

Outside the dev/test profiles it rejects the dev JWT secret, the default super-admin password and the tenant header fallback. Set real values, or run locally with ./gradlew bootRun (which uses dev).

"No workspace here" / 404 tenant_not_found

No tenant has this host as its slug, custom domain or the platform domain. Sign-up only adds users to an existing workspace, so create it first: sign in at admin.localhost and use Platform → Tenants → Provision tenant, or set APP_SEED=true in .env (Docker) or run ./gradlew bootRun --args='--app.seed=true' for the demo tenants acme and globex. If the tenant does exist, check APP_BASE_DOMAIN and that your proxy forwards the original Host.

Port 5432 is already in use

A local PostgreSQL is running. Stop it, or point the backend at it with DB_URL, DB_USER and DB_PASSWORD.

No e-mail arrives

In dev every message goes to Mailpit at localhost:8025. Sending happens after the database commit and retries a few times; failures are logged with the request id.

"Install app" doesn't appear

The service worker is off in npm run dev. Try npm run build && npm run preview, on localhost or over HTTPS.
